# Pisacoma Android App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline (the user forbids subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native Kotlin/Compose Android app that mirrors the Qwik site (https://quiz-qwik.vercel.app) screen for screen, with all content bundled, built and released by GitHub Actions from the public repo `crispinekkovendas-blip/pisacoma-android`.

**Architecture:** Single `MainActivity`, Navigation Compose with one destination per site route, repositories that lazily parse JSON from `assets/` (copied from the site by `tools/sync-content.mjs`), `UserState` over SharedPreferences using the site's localStorage key names, a Media3 `MediaSessionService` for hymn audio, `lottie-compose` for the home. A `Tokens.kt` carries the site's CSS values verbatim.

**Tech Stack:** Kotlin 2.2.10, AGP 9.1.0, Gradle 9.3.1 (wrapper), Compose BOM 2025.09.00, Material3, Navigation Compose 2.9, kotlinx.serialization 1.8, OkHttp 4.12, Coil 2.6, Media3 1.8, lottie-compose 6.6, android-youtube-player 13, JUnit 4; CI on GitHub Actions (ubuntu, Temurin 17).

**Spec:** `docs/superpowers/specs/2026-10-13-android-app-design.md`

## Global Constraints

- No Gradle runs on this PC. Every build/test/APK comes from GitHub Actions (`.github/workflows/android.yml`). Verify a task by pushing and reading the run (`gh run watch`, `gh run view --log-failed`).
- `minSdk = 24`, `targetSdk = 36`, `compileSdk = 36`, `applicationId = "pe.pisacoma.iglesia"`.
- Content in `app/src/main/assets/` is generated by `tools/sync-content.mjs` from `C:\Users\admin\sda-church-nextjs\quiz-qwik`; never hand-edit it.
- Colours, spacings, radii and font sizes come from the site's CSS, by the site's names, in `ui/theme/Tokens.kt`. Nothing eyeballed.
- UI copy is Spanish and identical to the site's strings (copy from the route files).
- User-state keys are the site's localStorage keys verbatim (`biblia:bookmarks`, `egw:<slug>:ch<n>:notes`, `escuela:<QID>:lecc<n>:day<d>:done`, `quiz.<slug>.v1`, `himnario.recent`, `inicio.videos.pausa`).
- No hover-only affordances; every tappable has a pressed state and ≥44 dp target.
- Home motion is never suppressed by the system's reduce-motion setting; the pause button is the way out.
- No purchases (Google Play account) without the user's explicit yes.
- Commit after every task with the attribution trailer; push so CI runs.

## Review Focus

1. **Offline on first open** — airplane mode, fresh install: Himnario, Biblia, EGW, Escuela, Quiz, Buscar must all render content; Videos shows its "sin conexión" state, not a spinner forever. (Task 15 UI test + Task 4 asset-loading test.)
2. **Saturday evening after sunset** — the home's Sabbath card must roll to next week's Friday, like the site (`sabbathTimes` when `now >= end`). (Task 5 unit test.)
3. **Bible references with ranges and semicolon continuations** ("1 Cor. 10:12 al 15", "Juan 3:16; 5:4-8") in lesson text must become the right verse sets. (Task 6 unit tests.)
4. **Hymn audio when the screen locks or the app is backgrounded** — must keep playing and be controllable from the notification; a second hymn replaces the first. (Task 9 manual check on the AVD + service test.)
5. **Orientation change on the home** — Lottie must switch portrait/landscape JSON without restarting playback position from a crash; state (paused) must survive. (Task 17 UI test.)
