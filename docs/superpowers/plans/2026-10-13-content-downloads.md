# Content Downloads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the heavy content out of the APK, make the first open a mandatory choice between «Descargar todo», «Descargar lo esencial», «Solo lo que uso» and «Mantener solo en línea», and serve every read through one store (bundled → disk → network).

**Architecture:** `content/` in the repo is the download origin (raw.githubusercontent). `ContentStore` implements the existing `AssetSource`, so no repository changes. A `CoroutineExceptionHandler` turns a missing file into one notice in `SiteScaffold`. A new `/descargas` route is the chooser, the progress view and the later management screen.

**Tech Stack:** Kotlin 2.2, Compose BOM 2025.09.00, kotlinx.serialization, OkHttp, JUnit4, Compose UI tests on the CI emulator. Every build runs on GitHub Actions (push → `build`; `gh workflow run android.yml` → `ui`; `v*` tag → `release`).

**Spec:** `docs/superpowers/specs/2026-10-13-content-downloads-design.md`

## Global Constraints

- No Gradle, emulator or adb on the PC. RED = push and read the failing CI run; GREEN = push and read the passing run. Node for `tools/sync-content.mjs` is fine.
- Kotlin and Gradle files are written with the Write/Edit tools, never bash heredocs (backslashes vanish on this box).
- Repository path strings (`data/biblia/43.json` …) do not change. Bundled files stay readable through the same `AssetSource`.
- Pref keys: `contenido.modo` ∈ {`todo`,`esencial`,`uso`,`en-linea`}, `contenido.pendiente` ∈ {`"1"`,`"0"`}; SharedPreferences name `pisacoma`.
- Download origin `https://raw.githubusercontent.com/crispinekkovendas-blip/pisacoma-android/main/content/` via `BuildConfig.CONTENT_BASE_URL`.
- Copy is Spanish in the site's offline-save voice (see spec §9). Sizes come from the manifest, formatted «29 MB» / «5,9 MB».
- Existing 105 unit and 23 UI tests stay green.

## Review Focus

1. Opening the app with no network on the first run: the chooser must still render (manifest is bundled) and «Solo lo que uso» / «Mantener solo en línea» must work; picking «Descargar todo» must show the error state, not hang. (Task 7 test `offlineFirstRunShowsError`.)
2. A partially downloaded store after the process is killed: the next open resumes without re-downloading stored files. (Task 4 `skipsStoredFiles`, Task 5 pending-flag resume.)
3. `en-linea` mode must never write to disk, including through the on-use path. (Task 3 `onlineModeNeverWrites`.)
4. A deep link on the first open: chooser first, then the deep-link target. (Task 7 `AppNavHost(after=)` + `DescargasTest.firstRunContinuesToDeepLink`.)
5. A corrupt or truncated download (HTTP 200 with a short body) must not be stored as valid: the store compares the byte count with the manifest. (Task 3 `rejectsShortBody`.)

@Serializable data class Manifest(val generated: String = "", val files: List<ContentFile> = emptyList()) {

    val persists: Boolean get() = this != EN_LINEA
    companion object { fun of(value: String?): ContentMode? } }
object Packs { val ORDER = listOf("himnario-es","himnario-pt","biblia","escuela","buscar","egw"); val ESSENTIAL = setOf("himnario-es","biblia","escuela","buscar"); fun label(id: String): String }

class ContentMissing(val path: String) : IOException("content not stored and offline: $path")

class ContentStore(
    private val bundled: AssetSource,
    val dir: File,                              // filesDir/content
    val manifest: Manifest,
    private val mode: () -> ContentMode?,       // null (first run) behaves like USO for reads
    private val fetch: suspend (String) -> ByteArray,   // relative path → bytes; throws IOException

    val missing: MutableStateFlow<String?>      // last path that could not be read offline
    override suspend fun read(path: String): String
    override suspend fun exists(path: String): Boolean
    fun isStored(path: String): Boolean
    fun storedBytes(): Long                     // sum of file sizes under dir
    fun storedCount(): Int
    suspend fun download(path: String)          // fetch + verify size + atomic write; no-op if stored
    fun clear()
}
