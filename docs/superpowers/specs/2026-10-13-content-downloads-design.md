# Content downloads — design

**Date:** 2026-10-13 · **Repo:** `crispinekkovendas-blip/pisacoma-android` · **Builds:** GitHub Actions only (the PC never runs Gradle, an emulator or adb).

## What the user asked

> Make once the app is open they must download all data, so they will have it offline... Make them choose download all, download essentials and keep online only and download only what they use.

So: the content leaves the APK, the first open shows a mandatory choice, and the app downloads according to that choice. The choice can be changed later.

## Decisions

1. **Content lives in the repo at `content/`**, not in the APK. The app downloads single files from
   `https://raw.githubusercontent.com/crispinekkovendas-blip/pisacoma-android/main/content/<path>`
   (`BuildConfig.CONTENT_BASE_URL`). Same paths as before (`data/biblia/43.json`, …), so no repository changes its path strings. Every push of `content/` is live at once; no extra hosting.
2. **What stays bundled in the APK** (`app/src/main/assets/`): the home (posters, Lottie, Lottie images), the 25 EGW covers (the home's EGW scene draws them), and the small indices every screen needs to render its frame: `bible-books`, `egw-index`, `featured-hymns`, `church`, `home-photos`, `anuncios`, `videos-channels`, licences. Roughly 14 MB.
3. **What downloads** (`content/`), grouped into packs the chooser can size:

   | pack id | label | files | size |
   |---|---|---|---|
   | `himnario-es` | Himnario Adventista | `data/himnario-es.json` | 1,1 MB |
   | `himnario-pt` | Hinários (portugués) | `data/himnario-pt.json`, `data/himnario-pt-novo.json` | 1,5 MB |
   | `biblia` | Biblia Reina-Valera 1960 | `data/biblia/*.json` (66) | 4,2 MB |
   | `escuela` | Escuela Sabática y Quiz | `data/escuela-sabatica.json`, `data/quizzes.json` | 0,5 MB |
   | `buscar` | Índice de búsqueda | `data/search-index.json` | 0,3 MB |
   | `egw` | 25 libros de Ellen G. White | `data/egw/*.json` (25) | 21,5 MB |

   **Essentials** = `himnario-es`, `biblia`, `escuela`, `buscar` (about 6 MB). **All** = every pack (about 29 MB). Sizes are computed from the manifest at run time, never typed in copy.
4. **Manifest** `content/manifest.json`, generated by `tools/sync-content.mjs` and also copied into the APK's assets (`manifest.json`) so the chooser can show sizes offline:
   `{ "generated": "<ISO date>", "files": [ { "path": "data/biblia/43.json", "bytes": 61234, "pack": "biblia" }, … ] }`.
5. **Four modes**, stored under the pref key `contenido.modo` (same store as the site's keys):

   | value | label | at first open | on every read |
   |---|---|---|---|
   | `todo` | Descargar todo | downloads every pack | bundled → disk → network, saved to disk |
   | `esencial` | Descargar lo esencial | downloads the essential packs | same; a non-essential file (an EGW book) is saved the first time it is opened |
   | `uso` | Solo lo que uso | downloads nothing | same: saved the first time it is used |
   | `en-linea` | Mantener solo en línea | downloads nothing | bundled → network; nothing written to disk |

   `contenido.pendiente` = `"1"` while the chosen packs are not fully on disk; the app resumes the download on the next open when it is online.
6. **`ContentStore : AssetSource`** replaces `AndroidAssetSource` in `Repos`. `read(path)`: bundled asset if present, else `filesDir/content/<path>` if present, else fetch; writes atomically (temp file + rename) unless the mode is `en-linea`. `exists(path)`: bundled, on disk, or listed in the manifest (the manifest is the authority on what exists; being offline is a `read` failure, not non-existence). When offline and the file is not stored, `read` throws `ContentMissing(path)` (an `IOException`).
7. **Missing content is one notice, not nine.** Every view model launches its loads with `ContentErrors` (a `CoroutineExceptionHandler`): a `ContentMissing` goes to `ContentStore.missing` (a `StateFlow<String?>`), anything else reaches the default uncaught-exception handler as before. `SiteScaffold` shows the notice over any screen while `missing` is set: eyebrow «Sin conexión», «Este contenido no está guardado en el teléfono. Conéctate a internet o guárdalo desde Descargas.», buttons «Reintentar» (re-creates the current destination) and «Descargas».
8. **Downloader** `ContentDownloader`: sequential file downloads for the chosen packs, skipping files already on disk, three retries per file, progress as `done/total` files and bytes, `failed` count, `StateFlow<DownloadState>` (`Idle`, `Running`, `Done`, `Error`). Application-scoped coroutine; survives screen changes, not process death (the pending flag resumes it on the next open).
9. **Screen `/descargas`** (`Route.Descargas`), Pastel skin, copy in the site's offline-save voice:
   - Eyebrow «— Sin conexión», title «¿Qué quieres guardar en este teléfono?», lede «Lo que guardes se lee sin señal. Puedes cambiarlo después desde el menú, en Descargas.»
   - Four option rows (tags `modo-todo`, `modo-esencial`, `modo-uso`, `modo-en-linea`): label, one-line description, size where it applies. Tapping one stores the mode; `todo`/`esencial` start the download and show the progress block; `uso`/`en-linea` finish at once.
   - Progress block (tag `descarga-progreso`): bar + «Guardando 12 de 98 archivos · 3,1 de 29 MB» → «Guardado en este teléfono · 29 MB» or «No se pudo guardar todo. Revisa la señal e inténtalo otra vez.» with «Reintentar».
   - Footer actions: «Continuar» (tag `descargas-continuar`, always enabled once a mode is chosen; the download keeps running) and, on later visits, «Borrar lo descargado» (deletes `filesDir/content`, keeps the mode) and «Completar» when files are missing.
   - **First open:** `MainActivity` starts at `Route.Descargas` when `contenido.modo` is unset, without the top bar or menu, and «Continuar» goes to the deep-link target or the home. Later visits come from the menu («Descargas · <stored size>» under the 11 destinations) and show the current mode marked «Actual».
10. **Tests.**
    - JVM: manifest ↔ files consistency, pack sizes and labels, `ContentStore` (bundled / disk / network / `en-linea` never writes / offline → `ContentMissing` / `exists` via manifest), `ContentDownloader` (skips stored files, counts failures, reports bytes) with a fake fetcher and temp dirs.
    - Emulator: the test APK carries `content/` as its own assets (`androidTest` assets srcDir) and a custom runner seeds `filesDir/content` and `contenido.modo=todo` before any test, so the existing 23 tests run unchanged and offline. New `DescargasTest`: first open shows the chooser (screenshot), «Solo lo que uso» leads to the home and stores `uso`; offline with an empty store, Biblia shows the missing-content notice (screenshot) and «Descargas» opens the screen.
11. **Release** v0.2.0 from the tag once the emulator run is green. The README and the vault note gain a «Descargas» section.

## Out of scope

Background downloads with a notification (WorkManager), delta updates of content, Play Asset Delivery.
